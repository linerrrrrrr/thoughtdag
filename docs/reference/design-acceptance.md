# 设计语言验收

本文件定义 ThoughtDAG 设计修改的验收要求。每次任务按实际影响范围选择检查，测试输出与截图只证明当次代码、数据和环境下的结果。本文件、规范样张或已有截图均不代表全站已经通过验收。

视觉规则见仓库根目录的 `DESIGN.md`，运行中的基础变量见 `src/index.css`。这两个文件属于项目源码，不是文档站页面。编辑、退出、草稿、焦点与显式提交统一执行 [interaction-contract.md](interaction-contract.md)；本文件只指定何时复核，不另行定义交互行为。

## 验收入口

- **规范样张：** 在应用开发服务器打开 `/design-system.html`，例如 [本地规范样张](http://127.0.0.1:5173/design-system.html)。用它比较语义字号、颜色、轮廓及组件组合；实际页面的覆盖样式、布局、缩放和交互仍需在对应功能中检查。
- **静态检查：** 在仓库根目录执行 `node scripts/check-design-system.mjs`，默认只检查、不写入。`node scripts/check-design-system.mjs --write` 将已建立 token 映射的基础字号、颜色和几何快照同步至 `DESIGN.md` 的受管字段；它不会推导未映射的组件组合或判断视觉重量。仅在这些定义确实改变且需要同步规范时使用写入模式。没有报告问题不等于所有 UI 已统一，也不等于通过视觉和交互验收。
- **实际界面：** 用同一份内容、主题、语言、窗口和画布缩放，对照受影响组件与同类参照。工具卡片以“更多操作”“对象格式”为参照；阅读区使用相同内容的节点正文与详情正文对照。

若文档、样张与实现不一致，先确认当前任务已经明确的目标和变量归属，再修正对应定义或记录待迁移项。不能仅为了使检查通过而更换已确认的视觉基准。

## 按修改规模选检查

| 修改范围 | 必需的检查 | 有对应影响时追加 |
| --- | --- | --- |
| 仅修改规范文字 | 链接、术语、事实来源及规则冲突 | 修改检查器时运行检查器；修改样张时查看其渲染 |
| 单个组件的样式 | 静态检查、实际组件与同类参照的视觉对照、受影响主题和窄宽度 | 字号、布局、状态或交互对应的浏览器回归 |
| 共享 token 或共享组件 | 静态检查、工具/阅读/画布代表样例、深浅主题与中英文；应用代码变更执行 build、lint | 与 token 影响相符的跨组件回归 |
| 编辑器、菜单、面板结构或画布行为 | 上述相关视觉检查，以及交互标准中受影响场景 | 草稿、关闭层级、响应式、缩放、几何或连接回归 |

检查通过后，只有新修改、失败或仍未解决的疑点才扩大或重复测试。低风险局部调整不要求运行所有脚本；全局字号、密度或轮廓调整应覆盖三个场景，不能只看规范样张。

## 七类规范的按需验收

| 类别 | 触发条件 | 验收要点 |
| --- | --- | --- |
| 字体层级 | 字号、字重、行高、字体或文本容器变化 | 按用途使用语义 token；显示与编辑不跳字号；正文、控件、元信息层级清楚；中文、英文及混排的实际字面协调 |
| 色彩与表面 | 背景、文字、边框、主题或状态色变化 | 使用对应语义颜色；工具表面、阅读表面和材料身份保持各自用途；深浅主题的文字与状态可辨，主题变化不改变几何 |
| 间距与布局 | padding、gap、宽高、分组或密度变化 | 同级内容对齐；组内与组间关系清楚；工具卡片沿用其参照的标题、字段和页脚节奏；长内容不挤出操作或制造整体横向滚动 |
| 圆角与轮廓 | radius、border、shadow、outline 或裁剪变化 | 外轮廓连续；嵌套轮廓随实际距离协调；选中描边和键盘焦点可见；端口、手柄及弹层不被误裁剪；不靠重复边框、底色和阴影同时强调同一区域 |
| 控件与图标 | 按钮、输入、分段选项、图标或操作行变化 | 字体、行高、图标、内边距和点击面积作为一组检查；同类控件基线一致；图标视觉重量协调；图标按钮有可访问名称；较大点击区域不必增加可见轮廓 |
| 状态与交互 | hover、selected、expanded、focus、disabled、loading、错误或退出行为变化 | 复核状态表达及其语义；禁用与选中不混淆；焦点不只靠鼠标可见；涉及行为时按现有交互标准分类、实现和验收 |
| 适配与缩放 | 响应式、阅读栏宽度、画布 zoom 或细节层级变化 | 按实际可用宽度检查；主要操作可达；长文本按用途换行或局部滚动；区分画布逻辑尺寸与屏幕尺寸；缩放保持图结构和当前编辑会话 |

### 字体角色的检查基准

以下像素值按浏览器默认根字号 16px、浏览器缩放 100% 计算，属于语义比例的检查基准。实际定义使用 `rem`，应保留用户调整浏览器字号的能力。

| 用途 | token | 默认字号 | 检查关系 |
| --- | --- | --- | --- |
| 元信息 | `--text-meta` | 12px | 时间、统计、来源等辅助信息；不能承担正文或常用操作标签 |
| 控件与标签 | `--text-control` | 14px | 按钮、菜单、字段标签及辅助操作保持同类密度 |
| 正文 | `--text-body` | 16px | 问题、回答与正文编辑态采用同一阅读尺度 |
| 组件标题 | `--text-title` | 16px | 通过用途、字重与行高区别于正文，不必再增加字号 |
| 小节标题 | `--text-heading` | 18px | 对应较低级内容标题 |
| 分区标题 | `--text-section` | 20px | 对应较高级内容标题 |
| 页面标题 | `--text-page` | 24px | 对应页面或一级内容标题 |

同时检查对应的 `--line-height` token 和字重。字号统一后仍需检查标题前后空间、段落节奏、编辑器行高和图标对齐。局部覆盖必须有明确用途，不能用缩小正文来修补容器空间不足。

## 工具、阅读、画布检查矩阵

| 场景 | 代表对象 | 内容与状态 | 适配重点 |
| --- | --- | --- | --- |
| 工具 | 顶部工具栏、“更多操作”、“对象格式”、排版面板 | 普通/选中/展开/键盘焦点/禁用；短标签与较长英文标签 | 标准窗口与窄窗口；阅读栏关闭与打开后的剩余画布宽度；功能分组和工具卡片不重叠 |
| 阅读 | 节点完整问答、右侧详情、材料阅读器 | 中英混排、长段落、各级标题、列表、代码、长链接；只读与编辑 | 同一正文在画布 100% 与详情中尺度一致；窄栏和低窗口下内容、保存及关闭入口可达；代码只在自身区域滚动 |
| 画布 | 对话/开始/便笺/文件节点、概览名称、连接与尺寸手柄 | 完整/概览/极简；单选/多选；正在编辑；长名称与真实文件扩展名 | 100% 阅读基准与缩远后的名称可读性；节点位置和存储尺寸稳定；轮廓、端口及命中区域随各自坐标规则工作 |

对共享视觉修改，选择一组中英文、深浅主题和宽窄状态覆盖上述矩阵。对局部修改，只扩展受影响的轴。例如只改变工具卡片 padding 时优先检查该卡片的窄宽度与页脚，不必重新覆盖所有节点连接路径。

### 缩放测量

画布内未经补偿的 CSS 长度会乘以画布 zoom 显示；屏幕固定工具栏和阅读栏不随画布 zoom 缩放。概览名称等元素采用有限的缩放补偿，须按实现的 clamp 验收，不能要求任何缩放下都维持固定像素大小。

- 字号检查同时记录 `getComputedStyle(element).fontSize`、画布 zoom 和预期的屏幕字号；只有一层画布缩放且没有额外变换时，屏幕字号才可按“计算字号 × zoom”估算。
- 尺寸与命中区域使用 `getBoundingClientRect()` 或实际指针操作检查；存储的节点宽高属于画布逻辑尺寸，不能直接与屏幕矩形比较。
- 比较截图时固定浏览器缩放和设备像素比。设备像素与 CSS 屏幕像素分开记录，避免把截图像素差当成 token 差异。
- 语义缩放切换、编辑保护及草稿恢复沿用交互标准；本文件不增加另一套阈值或退出规则。

## 视觉重量的人工对照

先在完整界面中看主次，再查看组件局部。相同数值只能证明量尺一致，以下判断需要真实渲染：

1. 当前任务与主要操作是否容易找到；提示、快捷键和元信息是否过度抢眼。
2. 一组控件是否被外壳、轨道、按钮、描边和阴影重复包围；分组能否用留白清楚表达。
3. 相同角色的选中、展开和悬停是否保持一致的强调方式，同时保留各自语义。
4. 中文字面、英文标签和不同路径密度的图标是否均衡；对齐外框后，内容是否仍显偏上、偏重或拥挤。
5. 圆角附近的内边距、分隔线与背景是否连续；节点、工具卡片和详情是否各自符合所属场景。

记录具体组件、主题、语言、宽度、zoom 与发现的问题。修正后对照相同条件复核；不能用不同内容或不同裁切的截图证明改善。

## 现有回归入口

以下脚本名是可选路由，表中描述为覆盖范围，不是通过结果。执行前查看脚本最新断言；已有脚本也可能因实现变化而过时。

| 影响范围 | 命令 | 现有覆盖重点 |
| --- | --- | --- |
| 设计快照同步脚本 | `npm run test:design` | 字号及深浅主题变化检出、别名解析、循环或缺失引用、同步幂等性与正文保留 |
| 规范样张 | `npm run test:design-ui` | 样张字号、表面、窄宽度、焦点、草稿与完整页面滚动，以及无 API/浏览器存储副作用；不能替代实际功能回归 |
| 共享字号、编辑态与概览文字 | `node scripts/test-typography-ui.mjs` | 深浅主题、中英文、节点/380px 阅读栏的字号与行高、编辑态、60%/30% 概览屏幕字号、宽窄菜单 |
| 顶部控件和响应式收纳 | `node scripts/test-toolbar-responsive-ui.mjs` | 不同窗口、语言与阅读栏宽度下的单行布局、溢出入口、搜索、焦点恢复 |
| 工具卡片外壳和切换 | `node scripts/test-toolbar-cards-ui.mjs` | 卡片显示位置、宽度、切换、草稿保留及窄屏 |
| 问答与详情排版 | `node scripts/test-conversation-gui-ui.mjs` | 节点/详情、窄卡片、元信息编辑和匹配条件下的截图；`BASELINE=1` 仅采集现状，不能作为行为验收通过 |
| 详情面板与画布协同 | `node scripts/test-node-details-ui.mjs` | 阅读对象与选区独立、切换/关闭、面板宽度及窄屏行为 |
| 编辑、退出和焦点 | `node scripts/test-edit-dismiss-ui.mjs`、`node scripts/test-layer-dismiss-ui.mjs` | 现有交互标准中的编辑边界、草稿、嵌套层和焦点；按修改场景选择 |
| 缩放与首问输入 | `node scripts/test-semantic-zoom.mjs`、`node scripts/test-node-input-zoom-ui.mjs` | 语义层级迟滞与挂载、首问显隐、编辑保护和缩放后的草稿 |
| 节点几何与对象格式 | `node scripts/test-node-geometry.mjs`、`node scripts/test-node-format-ui.mjs` | 逻辑尺寸、比例、撤销、格式卡片与实际命中操作 |
| 连接、排版与几何联动 | `node scripts/test-canvas-connections-ui.mjs`、`npm run test:layout` | 端口朝向、连接、预览/应用/撤销及箭头顺序；仅涉及这些行为时追加 |

浏览器脚本使用 `playwright-core`，需要已安装的 Chromium 浏览器；必要时设置 `CHROME_PATH`。各脚本默认地址不同，建议显式设置 `APP_URL` 指向同一个应用开发服务器。以下是 Windows PowerShell 示例，端口以实际启动输出为准：

```powershell
npm run dev -- --host 127.0.0.1 --port 5173
```

在另一个终端中运行所需检查：

```powershell
$env:APP_URL = 'http://127.0.0.1:5173'
node scripts/check-design-system.mjs
node scripts/test-typography-ui.mjs
```

上表中的浏览器脚本使用隔离的页面数据与本地测试内容。运行前保留脚本的 API 拦截设置，不用用户真实画布或真实模型调用替代测试 fixture。运行结果与截图通常写入脚本指定的 `local-tests/` 子目录；失败截图不代表其他未执行场景已通过。
